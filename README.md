# Channel Layer — الخطوة الأولى

طبقة قنوات مستقلة عن نوع التواصل (Channel-Agnostic). حالياً تدعم
Telegram كبيئة تطوير، وجاهزة لإضافة WhatsApp / Instagram / Facebook
لاحقاً دون إعادة هيكلة أي كود.

## البنية

```
channel_layer/
  core/
    channel_interface.py   # العقد الموحّد لأي قناة (IncomingMessage/OutgoingMessage)
    message_router.py      # الموجّه المركزي (لاحقاً: نقطة دخول الذكاء الاصطناعي)
  channels/
    telegram_channel.py    # كونيكتور Telegram (التطبيق الوحيد الحالي للعقد)
main.py                    # نقطة التشغيل - الملف الوحيد الذي "يعرف" أننا نستخدم Telegram
```

## التشغيل والاختبار

1. أنشئ بوت تيليجرام جديد:
   - افتح تيليجرام وابحث عن `@BotFather`
   - أرسل `/newbot` واتبع التعليمات
   - سيعطيك BotFather توكن مثل: `123456789:ABCdefGhIJKlmNoPQRstuVWXyz`

2. ثبّت المتطلبات:
   ```
   pip install -r requirements.txt
   ```

3. اضبط التوكن كمتغير بيئة:
   ```
   export TELEGRAM_BOT_TOKEN="التوكن_الذي_حصلت_عليه"
   ```

4. شغّل النظام:
   ```
   python main.py
   ```

5. افتح تيليجرام وابحث عن اسم البوت الذي أنشأته، وأرسل له أي رسالة
   (مثلاً: "شكد سعر تنظيف الأسنان؟").

6. **النتيجة المتوقعة**: يرد عليك البوت فوراً برسالة تؤكد أن
   الرسالة مرّت بنجاح عبر: تيليجرام → العقد الموحّد → الموجّه
   المركزي → العقد الموحّد → تيليجرام.

   في الطرفية (terminal) سترى أيضاً سطرين لكل رسالة (`[IN]` و
   `[OUT]`) يوضحان أن الأنبوب الكامل يعمل من طرف لطرف.

## لماذا هذه الخطوة مهمة تجارياً

هذا ليس "تجربة تقنية" منفصلة عن المنتج - هذا هو **نفس الأنبوب**
الذي سيحمل لاحقاً محرك الذكاء الاصطناعي الحقيقي ومنطق الحجوزات.
عندما نوقّع أول عيادة، الانتقال من Telegram إلى WhatsApp Business
API سيعني فقط إضافة ملف `whatsapp_channel.py` جديد وتغيير سطر واحد
في `main.py` — دون إعادة كتابة أي منطق أعمال أو اختباره من الصفر.

## الخطوة التالية (بعد موافقتك)

إضافة منطق عمل حقيقي بدل `stub_business_logic` في `message_router.py`:
أول سيناريو محادثة كامل (استقبال استفسار → عرض الأسعار → تأكيد
حجز موعد) — وهو ما سيتحول لاحقاً إلى أول عرض حي أمام عيادة فعلية.
